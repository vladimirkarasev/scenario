# Code Comments

Комментарии в коде — **только у методов/функций** (докблоки). Инлайн-комментарии внутри тела метода не добавлять.

**Why:** Пользователь явно попросил не засорять тело методов комментариями; пояснения должны жить в докблоке метода.

**How to apply:**

- **Докблок метода/функции** — допустим и приветствуется: короткое пояснение назначения + `@param`/`@return` по необходимости (PHP), JSDoc/типы (TS).
- **Внутри тела метода** — никаких поясняющих `//`-комментариев. Если логика непонятна без комментария — переименовать переменную/выделить метод с говорящим именем, а пояснение вынести в докблок.
- Относится к PHP (`module/`, `app/`), TS и Vue (`<script setup>`), включая composables и сервисы.
- Не трогать существующие инлайн-комментарии массово без запроса — применять правило к новому и редактируемому коду.

Применяется проактивно при написании/правке кода.
